# Updates

PhoneDeck can update the **installed Windows app** from public GitHub Releases.
This is not the Android APK updater and it does not publish builds: it only
checks the release feed, downloads the newest NSIS installer, and restarts into
it.

## How it works

- The packaged Windows app contains `resources/app-update.yml`, generated by
  electron-builder from the `publish` block in `apps/desktop/electron-builder.yml`.
- About five seconds after startup (and whenever the user chooses **Settings →
  Updates → Check for updates**), the main process asks the GitHub Releases feed
  for `latest.yml`.
- If a newer version exists, `electron-updater` downloads
  `PhoneDeck-<version>-Setup.exe` automatically, verifies its SHA-512 against
  `latest.yml`, and reports progress to the renderer.
- When the download is complete, the top bar shows **Update ready** and
  **Settings → Updates** offers **Restart and install**. This quits PhoneDeck
  and runs the downloaded installer, then reopens the app.
- `autoInstallOnAppQuit` is also enabled, so a downloaded update is applied the
  next time PhoneDeck exits normally even if the user does not press the button.
- Downgrades and pre-releases are disabled. A failed check can be retried; the
  raw error goes to `phonedek.log`.

Development builds and Linux/macOS builds report **Automatic updates are
unavailable** and never contact the feed. The feature runs only when
`app.isPackaged && process.platform === 'win32'`.

## First updater-enabled version

The updater cannot install itself into a build that does not contain it.

- **0.1.3 is the first updater-enabled Windows build.** Users on 0.1.2 or older
  must install the 0.1.3 `PhoneDeck-<version>-Setup.exe` manually once.
- From 0.1.3 onward, later versions can be installed from inside the app.
- **0.1.4 is the first release delivered through the updater** (from 0.1.3).

Keep the version in the root `package.json`, `apps/desktop/package.json`, and the
desktop `APP_VERSION` value in sync with the release tag. The updater compares
the installed app version against `latest.yml`.

## Publishing a release

1. Bump the version in the files above, run the gates:

   ```bash
   npm test
   npm run typecheck
   npm run build
   ```

2. Build the Windows installer from Windows (CI does this in the `desktop` job):

   ```bash
   npm run dist:win
   ```

   `dist:win` uses `electron-builder --win nsis --publish never`. Because the
   `publish` block is present, it still generates the updater metadata; it does
   not upload anything.

3. Confirm these files exist in `apps/desktop/release/`:

   ```text
   PhoneDeck-<version>-Setup.exe
   PhoneDeck-<version>-Setup.exe.blockmap
   latest.yml
   win-unpacked/resources/app-update.yml
   ```

   `latest.yml` is the public feed entry. The `.blockmap` enables differential
   downloads. `app-update.yml` is copied inside the installed app and tells it
   which repository to query.

4. Create a GitHub release with a tag matching the version, for example
   `v0.1.3`, and upload **all three public files**:

   - `PhoneDeck-<version>-Setup.exe`
   - `PhoneDeck-<version>-Setup.exe.blockmap`
   - `latest.yml`

   Do not upload only the `.exe`; without `latest.yml` and the matching
   `.blockmap`, clients cannot find or verify the update. The release must not
   be a draft, and the tag/version must be the newest non-prerelease release.

5. Optionally attach a `SHA256SUMS` file for manual verification. The updater
   does not need it; it verifies the SHA-512 recorded in `latest.yml`.

The repository is public, so no GitHub token, PAT, or account is needed for
either the app or the release feed. Never add a token to the app or to
`electron-builder.yml`.

### CI artifacts

The GitHub Actions `Desktop (Windows installer)` job runs the same build, then
checks that `latest.yml`, `app-update.yml`, and the `.exe.blockmap` were
produced. The `PhoneDeck-Windows` artifact contains the `.exe`, `latest.yml`,
and blockmap; the unpacked artifact contains
`resources/app-update.yml`. Upload those files to the GitHub release.

## Security and known caveats

- `electron-updater` verifies the installer's SHA-512 against `latest.yml`.
  That protects against a corrupted download, but **the installer is not
  Authenticode-signed**. Code signing is still absent, so Windows SmartScreen
  may warn on manual installs and updates. Users can choose **More info → Run
  anyway**.
- The renderer never receives filesystem or network privileges. It only sees
  update status and calls the three IPC methods `getUpdateStatus`,
  `checkForUpdates`, and `installUpdate`.
- GitHub rate limits public unauthenticated requests. If the limit is hit, the
  app shows a retry message and keeps working. Offline checks fail with a
  friendly message; retry when the network is back.
- Updates are downloaded to Electron's updater cache and applied by the NSIS
  installer. Per-user installs do not need administrator rights; an install
  that was elevated may prompt for elevation.
- Only stable releases are considered. Pre-release tags are ignored.
